Worklist

How worklist & MPPS work

The list

The query is a C-FIND at worklist level and changes nothing on the SCP. Scheduling filters go inside the Scheduled Procedure Step Sequence, which is what a conformant MWL SCP expects — a flat query is the usual reason a worklist comes back empty. The worklist SCP keys on the called AE; an MPPS step is attributed to the performed station AE, which is this station's AE Title from Settings — one fact that decides both. The engine warns when a row's scheduled station differs from it.

The search box sends one key: digits only become PatientID, a name (letters, or ^) becomes a PatientName wildcard, anything mixed becomes AccessionNumber. The tag beside the box says which was chosen; click it to pick a different key.

A query that fails is not an empty worklist. An unreachable RIS, a refused association or a timeout is said where the list is, in red, with the engine's own sentence — and any rows still on screen are labelled as the last answer that was read, not this one.

Only a fresh query changes the list. A row can leave the results for reasons that have nothing to do with the performed step — the date filter, the station AE, or the SCP's own rules — and it can stay in them even after a step was accepted. What the SCP did with a scheduled entry after a performed step is not visible from this side; some SCPs keep the entry, some drop it. The list re-reads itself every minute while this screen is open. The selected patient stays selected across a refresh, matched by study and scheduled step — or, for a row that names no study, by accession, step and patient ID. A row carrying none of those cannot be matched at all: the patient stays on the panel, the panel says the list no longer identifies which row they are, and nothing is re-pointed. Worklist rows to fetch in Settings caps the query with --limit; blank asks for the whole answer.

Performing an exam

Perform exam is one dcm mpps perform transaction: N-CREATE opens the step on the RIS, C-STORE sends the images to the archive, N-SET closes it. COMPLETED requires every instance found on disk to have been acknowledged. A shortfall makes the step DISCONTINUED and the run fails; there is no override. The RIS that takes the procedure step and the archive that takes the images are often different systems, so both are written out in full in the command even when they are the same — a default you cannot see is a default nobody can check. The archive is whichever saved peer holds the Archive role in Settings; with none set, the images go to the RIS peer.

Start only is the same transaction taken apart: dcm mpps start opens the step and leaves it IN PROGRESS, for when the images are sent by something else or the step has to stay open in between. The row then offers Complete and Discontinue. Adding a folder to an open step sends it with dcm send first and then completes the step naming those images — and only if every instance was acknowledged; otherwise the step is discontinued, for the same reason as above.

PerformedSeriesSequence is built only from instances the archive positively acknowledged, never from a folder listing. --series-from asserts what is on this disk rather than what the archive acknowledged, so it is only taken by default when every instance found in that folder was acknowledged — otherwise the N-SET would name images the archive may not hold.

The fields the panel calls Performed step ID and Performed station AE are Type 1 in the N-CREATE — the engine refuses to open a step without either, which is why an empty one is said in amber on the panel rather than left to the run. The station AE follows this station's AE Title from Settings unless it is typed over for one patient; picking another patient puts it back.

A discontinuation reason is a code item — value^scheme^meaning, e.g. 110513^DCM^Discontinued for equipment failure — so the panel offers the standard DCM reasons by name and puts the triplet on the command line. Free text is refused by the engine: a coded reason has to be a real code, not one invented here. Another code… is there for a site with a private scheme.

When the images carry a different study

The RIS invented its Study Instance UID before these pictures existed, so nothing on disk could be carrying it. A step naming one study while the images carry another is a pair of records the archive can never reconcile. So the station does what a modality does: a copy carrying the worklist's study, patient and accession is written to a staging directory and sent (--adopt-worklist-identity). Your folder is not modified; Series and SOP Instance UIDs are left alone — they belong to the equipment, not the order.

Sending the images exactly as they are (--allow-study-mismatch) is offered only when Settings › Engineer options allows it. The archive then files the images under one study while the RIS closes a step naming another, and nothing reconciles afterwards. Pick it only when that is the thing you are testing — or when a private tag matters, since the re-stamped copy is written by a dataset writer that does not carry private tags across.

Re-stamping belongs to dcm mpps perform. Images added to a step that was opened with Start only are sent by dcm send, which copies nothing and changes nothing — so a folder carrying a different study cannot be added to an open step at all, and the panel refuses it rather than filing the images under one study while closing a step that names another. Perform that study as its own exam instead.

A folder holding several studies cannot be re-stamped: Study Instance UID is the key the RIS reconciles the step against, so sending two studies under one step would attribute half these images to the wrong order, and merging them would make a study that never existed. Split the folder and perform one step per study.

What the status pills mean

A pill on a row says what this app sent, from this window, in this session. It is never a statement about what the RIS now shows: MPPS has no query service — there is no C-FIND for performed procedure steps — so no peer was asked. A step shown IN PROGRESS may already have been closed at someone's console, and a step this app did not perform never appears. To see what the SCP now returns, query again.

Open steps live in this window and nowhere else. Nothing is written to disk, so quitting forgets them: the MPPS SOP Instance UID printed by start is the only handle on a step, and once this window is gone nothing can hand it back. Close every open step before quitting. A step is closed on the system that took the N-CREATE, not whatever the peer chip says now; if someone else already closed it, that peer refuses the N-SET and says so. Both COMPLETED and DISCONTINUED are final.

How sending works

          
The accounting

          
C-STORE a folder to a peer, then report exactly what was acknowledged. A partial transfer is a failure: found, sent and acknowledged are counted separately and the run only succeeds when all three agree.

          
The speed presets

          
Normal — one association at a time: ordinary clinical traffic, and the only setting that adds nothing to the receiver's association count. Fast — four at a time: a backlog or a migration, to a receiver you already know tolerates a handful at once. Very fast — eight at a time: a bulk move you are watching, on a link with the bandwidth to make the concurrency pay. Insane — sixteen at a time: a benchmark against a receiver you own, not a thing to point at someone else's archive.

          
Insane is a benchmark setting, against a receiver you own. The receiver decides how many associations it will accept, and going past that limit gets the extras rejected. A rejected association is retried, so this usually does not arrive as a slower run or as a shortfall between instances found and acknowledged: it arrives as a run that reports a narrower parallelism than the sixteen it asked for, at the bottom of the output. A study also has to split into at least sixteen chunks before sixteen associations can run at once, so a small one runs narrower than this no matter what the receiver allows.

          
Chunk size and parallel, under Advanced

          
A preset sets both of these together, because setting one alone caps the other. A chunk size typed there replaces the preset's half of that and leaves its association count in place — the command carries both flags and the engine names what it displaced. An association count typed there replaces the preset outright: the command drops --speed, because a preset that has lost its width would still be sizing the chunks off your number. Clear the field to go back to the preset.

          
Retries, timeout and chunk size fall back to Settings › Defaults when the field is blank. Whatever ends up in force is on the command line below the button.

Receive images

          
        

        

          
How the receiver works

          
A permissive C-STORE SCP: it accepts every presentation context offered, acknowledges what arrives and logs it. It is a test receiver, not an archive — nothing is indexed and nothing is queryable.

          
Leave Save arriving images to empty and instances are acknowledged and discarded, which is what you want when the question is only whether the sender can reach you. Give it a folder and everything that arrives is written there.

          
Under Advanced: an allowlist of calling AE Titles refuses associations from anything else, so you can prove a sender is being rejected for the reason you think. Stop acknowledging after N is a fault injector — the receiver accepts the association and then stops acknowledging, which is how you reproduce a shortfall on the sending side on purpose. Both are test knobs; leave them empty for an ordinary receive.

          
The run holds the port until you stop it. The output below is the whole record of what arrived.

Query a peer

          
        

        

          
How querying works

          
C-FIND asks the peer what it holds and changes nothing. A peer can accept your images and still return zero matches here — storing and indexing are different operations, and some archives index on a schedule.

          
Matching keys are DICOM keyword = value. Wildcards * and ? are allowed, and dates take a range: 20260101-20260201. An empty value asks the peer to return that attribute rather than match on it — which is how you find out what it will tell you.

          
Level decides what a match is: a study, a series, an image, or a scheduled procedure step (Worklist). Worklist here is the raw query; the Worklist screen is the same C-FIND with the scheduling keys routed into the Scheduled Procedure Step Sequence, which is what an MWL SCP expects.

          
Limit stops reading after that many matches. It is a client-side stop, so the peer may already have done the work.

DICOMweb

          
        

        

          
How DICOMweb works here

          
The server and its credentials

          
The chip on each tab picks one of the saved base URLs; they are edited in Settings. Authentication comes from the environment — DCM_WEB_TOKEN (Bearer) or DCM_WEB_USER / DCM_WEB_PASS (Basic), set before launching the app. There is deliberately no token field: a credential typed into a window is a credential in a window.

          
Test

          
A QIDO-RS request that asks for nothing: it answers whether there is a DICOMweb service at this URL and whether your credentials open it. Nothing is sent.

          
Send

          
STOW-RS uploads a folder of DICOM files, with the same found/sent/acknowledged accounting the DIMSE send screen uses. Chunk size, retries and timeout fall back to Settings › Defaults when blank.

          
Query

          
QIDO-RS searches for studies, series or instances and changes nothing. Blank fields are simply not sent.

          
Hub

          
A local DICOMweb server (STOW and QIDO) to point the other tabs — or any DICOMweb client — at. Save arriving studies to empty means accept and discard. Pre-populate index from serves an existing folder of DICOM files at startup, so there is something to query straight away.

          
Under Advanced: Require token is a test knob — clients without that Bearer token get 401s, which is how you reproduce an auth failure. It is not real security. Reject after N stops accepting partway through, on purpose, so a client's failure handling can be watched.

Tools

          
        

        

          
What these tools do

          
Every tab here works on local files and sends nothing to any peer.

          
Inventory

          
Reads metadata only — it stops before pixel data, so it is fast on big trees. Break down per series also flags colliding Series UIDs, which is the usual sign that two studies were merged into one folder or that something rewrote UIDs on the way in.

          
Tags

          
Dumps the tags in a file or folder. It reads metadata only and never prints pixel data. The filter takes a keyword, a tag or a value, and /regex/ is allowed. By default one file per series is read, because the tags that differ per instance are rarely the ones being looked for; Every file reads all of them.

          
Edit

          
Load a study or a single file, change values, then write the result to a new folder. The source is never modified. Preview only shows what would change and writes nothing — it is this tab's own switch, about the disk rather than a peer, and Rehearsal mode adds the same flag from the other direction.

          
UIDs are structural, so editing one is gated behind Allow editing UIDs. Changing a Series or Study UID on some instances and not others splits a study into pieces no archive will put back together.

          
De-identify

          
Best-effort, not certified. It does not read pixel data, so burned-in annotations survive, and identifiers inside nested sequences (SR, presentation states) can survive. Always inspect a sample before sharing anything this produces. The source is never modified; UIDs are remapped consistently across the copy so the study stays whole.

Speed test

          
        

        

          
How to read a sweep

          
Each run in a sweep uses its own calling AE Title — the prefix with a run number appended — so you can pick any single run out of the peer's ingress logs afterwards.

          
The numbers

          
Throughput is measured against bytes on disk, so compressing a study does not flatter the number. "On the wire" is what the network actually carried. Which transfer syntax is used is the peer's choice — the table shows what it negotiated, not just what was asked for. Width is measured the same way: it is the associations the peer actually had open at once, not the number the run asked for, and it is a floor — it can read one low on a run whose last chunks drain early, and never reads high.

          
Finding a receiver's ceiling

          
This is how you find the receiver's ceiling — read the Width column and the Ack column afterwards, because neither answers the other's question: a refused association is retried with no backoff, so the attempts burn out in milliseconds, and the run either finishes clean at a width it never reached or ends with instances the receiver never acknowledged. Width says whether it ran as wide as asked; the counts say whether all of it arrived.

          
Chunk size across a sweep

          
A chunk size in the field below applies to every run and overrides each preset's own sizing, so a preset may not reach its association count. Clear it to compare the presets as they ship. Association counts typed into Also try are each sent as --parallel, which overrides the preset's chunk sizing in the same way.

Connect to Claude

          
        

        

          
What MCP is doing here

          
MCP is how an assistant calls a local program as a tool. Registering this server hands Claude the same dcm engine this app runs — not a copy, and not a service in the cloud. Every call happens on this machine, against the peers you name.

          
It requires dcm installed and on your PATH. If claude mcp add is not found, install Claude Code first. The one-line registration is run once; Claude Desktop instead reads the JSON block from its config file, so that one needs a restart to take.

          
The tools are the read-and-send half of this app. Nothing that closes a procedure step is exposed: MPPS is a transaction against a RIS, and it is not a thing to hand to something that cannot see the worklist row it belongs to.

        

        
Let Claude (or any MCP client) drive these DICOM operations as tools.


        

          Checking whether dcm is on your PATH…

Test a connection

          
          
        

        

          
What C-ECHO proves

          
C-ECHO opens an association, asks the peer to verify it, and closes. It proves three things together: the host and port are reachable, the peer accepts this station's AE Title as a caller, and it answers to the called AE you typed.

          
It proves nothing about storage. A peer can verify happily and still refuse every image you offer it, because the presentation contexts it accepts for C-STORE are a separate negotiation. A failed echo is conclusive; a successful one is only the first step.
